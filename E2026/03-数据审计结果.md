# 2026 E 题：首轮数据审计结果

运行命令：python E2026/audit_data.py --data-root ../E题数据/E题数据 --out E2026/data_audit.json。脚本只读原始附件，完整机器可读结果见 data_audit.json。

## 已核事实

| 数据 | 审计结果 |
|---|---|
| 附件1 | 100 个视频、Excel 100 行；按 (video_id, clip_id) 归一后双向完全匹配，均为 100 个不同主键；Positive 57、Neutral 25、Negative 18 |
| 附件2 | Excel 4850 行，其中 train 3395、valid 728、test 727；Positive 2370、Negative 1380、Neutral 1100。aligned_50.pkl 为 993,842,861 字节，unaligned_50.pkl 为 2,897,003,035 字节 |
| 附件3 | 对齐版、未对齐版各 30 个 pkl；每个文件顶层均为 test 字典 |
| 附件4 | 对齐版、未对齐版各 20 个 pkl 和 20 个视频；每个 pkl 是直接的样本字典，而非附件3的 test 包装 |

本机审计时可用内存约 2.4 GB，本轮没有反序列化附件2两个大文件，因此其内部字段、划分数量和 ID 唯一性仍待核。Excel 的 mode 列不是大 pkl 内部划分的独立验证。

## 关键字段差异

| 数据 | 实际字段 | 一个样本的形状 |
|---|---|---|
| 附件3对齐版 | text_bert, audio, vision | (1,3,50), (1,50,74), (1,50,35) |
| 附件3未对齐版 | raw_text, audio, vision | 文本长度 1；语音、视觉分别为 (1,500,74), (1,500,35) |
| 附件4对齐版 | id, raw_text, text, text_bert, audio, vision | text (50,768)，text_bert (3,50)，audio (50,74)，vision (50,35) |
| 附件4未对齐版 | 上述字段另有 audio_lengths, vision_lengths | text (50,768)，语音、视觉各 500 个位置 |

附件3对齐版没有预计算 text，不能用附件2的 text 向量训练后直接推理。若选 aligned，须核对附件2训练集是否有 text_bert，并让训练、验证和附件3推理共用相同文本编码路径。附件3没有显式 id，结果 CSV 需要把文件名与样本 ID 的映射写清楚。

审计脚本记录了最长全零连续段，但目前不能把尾部填充与局部缺失分开。附件3也没有显式有效长度；计算缺失率前须先确定有效位边界。

## 下一步

1. 在内存足够的环境中读取附件2，核对 train/valid/test 数量、字段、形状、有效长度、主键唯一性与标签映射。
2. 建立附件3/4统一适配器，显式记录版本、字段来源、有效位与文件名映射。
3. 用固定小批量验证文本编码、三模态张量和标签能进入同一预测模型，再开始基线训练。
